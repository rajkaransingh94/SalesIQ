# SalesIQ — Sales Analytics Dashboard

A full-stack sales analytics platform. Fictional retail data lives in MySQL, is
aggregated with SQL, exposed through a Node.js/Express REST API, and rendered
in a React + Recharts dashboard.

> All data in this project is randomly generated sample data for
> demonstration purposes. It does not represent a real business, product
> catalog, or customer list.

```
MySQL Database → Node.js + Express → REST API → React + Vite → Analytics Dashboard
```

---

## Features

- KPI summary: total revenue, profit, orders, customers, profit margin
- Monthly revenue/profit trend line chart (24 months of history)
- Revenue & profit breakdown by product category and by region
- Top-10 products and top-10 customers, ranked by revenue
- Region / category / date-range filtering across every endpoint
- Loading, error and empty states throughout the UI
- Responsive layout (desktop → tablet → mobile)
- ~2,200 orders / 5,400 order items generated by a repeatable data script

## Architecture

```
SalesIQ/
├── database/
│   ├── schema.sql          # tables, keys, indexes
│   ├── generate-seed.js    # generates database/seed.sql
│   └── seed.sql            # generated INSERT statements (sample data)
├── backend/
│   ├── server.js           # Express app entry point
│   ├── db.js                # MySQL connection pool
│   ├── routes/               # one file per resource
│   ├── controllers/          # SQL queries + response shaping
│   └── utils/queryFilters.js # shared region/category/date filter builder
└── frontend/
    └── src/
        ├── components/      # Navbar, KPICard, charts, DataTable, Filters
        ├── pages/Dashboard.jsx
        └── services/api.js  # fetch wrapper around the REST API
```

Data flows one direction: the React dashboard calls the Express REST API,
which runs parameterized SQL against MySQL and returns JSON. No analytics
values are hardcoded in the frontend — every number on the dashboard is the
result of a `GROUP BY` / `SUM` query.

## Database schema

```
categories (id, name)
    ↓
products (id, name, category_id, price, cost)

customers (id, name, email, region)
    ↓
orders (id, customer_id, order_date, region)
    ↓
order_items (id, order_id, product_id, quantity, unit_price, discount)
```

Revenue and profit are derived, not stored:

```
line revenue = quantity * unit_price * (1 - discount / 100)
line profit  = line revenue - (quantity * product.cost)
```

## API endpoints

All endpoints accept optional query filters: `region`, `category`,
`startDate` (YYYY-MM-DD), `endDate` (YYYY-MM-DD).

| Method | Endpoint                  | Description                                  |
|--------|----------------------------|-----------------------------------------------|
| GET    | `/api/health`              | `{ "status": "OK" }`                          |
| GET    | `/api/dashboard/summary`   | Total revenue, profit, orders, customers, margin |
| GET    | `/api/sales/monthly`       | Revenue & profit grouped by month             |
| GET    | `/api/sales/category`      | Revenue & profit grouped by category          |
| GET    | `/api/sales/region`        | Revenue & profit grouped by region            |
| GET    | `/api/products/top`        | Top products (`?sortBy=revenue\|profit&limit=10`) |
| GET    | `/api/customers/top`       | Top customers by revenue (`?limit=10`)        |
| GET    | `/api/meta/filters`        | Valid regions/categories for the filter UI    |

Example: `GET /api/sales/category?region=North&startDate=2025-01-01`

## Installation

### Prerequisites

- Node.js 18+
- MySQL 8.x running locally (or a cloud MySQL instance)
- Git

### 1. Clone and install

```powershell
git clone <your-repo-url> SalesIQ
cd SalesIQ

cd backend
npm install
cd ../frontend
npm install
cd ..
```

### 2. Create the database

```powershell
mysql -u root -p < database/schema.sql
```

Regenerate fresh sample data any time with:

```powershell
node database/generate-seed.js
mysql -u root -p < database/seed.sql
```

### 3. Configure environment variables

```powershell
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
```

Edit `backend/.env` with your local MySQL credentials:

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=YOUR_PASSWORD
DB_NAME=sales_dashboard
PORT=5000
CORS_ORIGIN=http://localhost:5173
```

`frontend/.env` only needs the API base URL (already correct for local dev):

```env
VITE_API_BASE_URL=http://localhost:5000/api
```

## Running locally

```powershell
# Terminal 1 — backend
cd backend
npm run dev

# Terminal 2 — frontend
cd frontend
npm run dev
```

- API: http://localhost:5000/api/health
- Dashboard: http://localhost:5173

## Deployment

The intended free-tier path is:

```
GitHub → static frontend host → Node/Express host → managed MySQL
```

Free-tier platforms and their limits change often, so verify current
availability before deploying (ask your assistant to check, or search
directly) rather than relying on older information. At a high level you'll
need:

1. A MySQL-compatible database host, with `database/schema.sql` and
   `database/seed.sql` (or your own data) loaded.
2. A Node.js host for `backend/`, with the same environment variables as
   your local `.env` (pointing at the cloud database) and `CORS_ORIGIN` set
   to your deployed frontend's URL.
3. A static host for `frontend/` (`npm run build` outputs `frontend/dist`),
   with `VITE_API_BASE_URL` set to your deployed backend's URL.
